# Runtime cognition — 0.5

Park implementation until the planet clears the release criteria in `CLAUDE.md`.
Handle uncertain discretionary escalations first; preserve immediate reflexes and the learned fast path.
Run a local sidecar on the Apple M4 Max with 128 GiB memory.

## Model and execution

Start with pinned Strands Decider Qwen3.5 2B weights and pinned MLX serving code.
Verify independent-state batching explicitly: batching questions against one shared state does not
establish batching across creatures. Consult the [Strands inference documentation](https://github.com/strands-labs/strands-decider/blob/main/docs/inference.md).
Keep [Clef/Clef-Flash](https://blog.cloudflare.com/clef-decision-models/) and
[Jev](https://docs.typesafe.ai/introduction) as evaluation alternatives.

Replace the individual-request path in
`addons/local_agents/creatures/cognition/CognitionScheduler.gd` with a genuine asynchronous batch queue.
Its concurrency budget rejects work; the queued activity indicator does not establish queued execution.
Remove automatic heuristic-teacher substitution from the model path; return typed failures.

## Contract

- Accept request ID, creature generation, state version, sensed context and legal action choices.
- Return selected action, distribution, confidence, model revision or typed failure per request.
- Queue fairly; deduplicate pending work per creature and keep each creature's observations private.
- Reject results after death, replacement, state invalidation or reflex preemption; apply valid results
  at the simulation boundary.
- Keep confidence diagnostic until domain evaluation supports a behavioral policy.

## Completion gates

- Verify actual batched model execution, legal actions, cancellation, fairness, overload, service failure
  and batch-versus-single consistency.
- Activate and demonstrate the sidecar with the game on this hardware, including contention with planet
  compute; select batch limits from measured local throughput and latency.
- Pin model and serving revisions before verification; record reproduction commands with the implementation.
